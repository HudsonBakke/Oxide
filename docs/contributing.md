# Documentation and style

Describe the contract of each public type, field, enum value, constructor, and
operation in the source language: Rustdoc for Rust, XML documentation for C#,
docstrings and attribute comments for Python, and Doxygen for C. Include units,
coordinate space, valid ranges, ownership, and failure behavior where relevant.
Document what the implementation actually guarantees.

Keep imports at the top, followed by constants/types and their implementations.
Keep constructors and factories together, related property accessors adjacent,
and lifecycle callbacks in initialization/update/draw order. In Python, preserve
import and definition order when it affects module initialization. In C and C#,
preserve field and enum order because these declarations participate in the ABI.
Avoid moving initialization code during a formatting-only change.

Use Rustfmt for Rust, Black for Python, and ClangFormat with the root
`.clang-format` for C, C#, and HLSL. Do not reformat generated bytecode or asset
files. The formatters only need installing when doing source-maintenance work:

```powershell
rustup component add rustfmt
python -m pip install black==25.1.0 clang-format==19.1.7
```

```powershell
cargo fmt --all
python -m black bindings/python examples/python tests
Get-ChildItem include, examples/c, bindings/csharp, examples/csharp, tests/csharp, shaders -Recurse -File |
    Where-Object { $_.Extension -in '.h', '.c', '.cs', '.hlsl' } |
    Where-Object { $_.FullName -notmatch '[\\/](bin|obj)[\\/]' } |
    ForEach-Object { clang-format -i $_.FullName }
```

Build the language-specific API documentation:

```powershell
cargo doc --locked --no-deps --open
dotnet build bindings/csharp/Oxide.NET/Oxide.NET.csproj -p:GenerateDocumentationFile=true
python -c "from oxide import ContentManager; help(ContentManager)"
```

Python help imports the package and therefore requires the native DLL. C#
documentation is emitted as XML beside the binding assembly. The C header can
be processed with `doxygen docs/Doxyfile` after installing Doxygen; open
`target/doxygen/html/index.html` to browse it.

Run the commands in the root README to validate builds and tests. For a
documentation or style change, also compare Python syntax trees with docstrings
removed and compare non-comment tokens in native source. Review any formatter
changes to imports, optional trailing commas, or numeric spellings separately.

All tests, fixtures, test helpers, and test runners belong under `tests/`.
Do not add test modules, `#[cfg(test)]` branches, or test-only helpers to `src/`.
See [the test guide](../tests/README.md) for the private integration harness and
language-specific commands. CI enforces this layout before building.
